# Trusted cases share frontend and backend runtimes

V1 case frontends share a browser document and Vite application. The platform selects and loads a case, owns the outer launcher and playthrough identity, constructs the Case SDK, and mounts or unmounts the case in a dedicated root. The case owns the gameplay viewport, internal navigation, visuals, and styles. React trees must unmount fully, and case-created listeners, timers, subscriptions, observers, temporary DOM changes, and other effects must be cleaned up. Scoped styles are preferred where practical. A Phone-to-Terminal-to-Phone switching test must exercise lifecycle cleanup.

Case backends are explicitly registered first-party Go packages in one process. The platform authenticates access, resolves the pinned case/version, coordinates action transactions, and persists resulting state and events; cases interpret their own actions. Shared process failures and accidental frontend interference are accepted risks for reviewed code, handled as normal engineering defects rather than hostile-code isolation failures. Defensive request limits, panic recovery where appropriate, and cooperative cancellation remain relevant.

The platform owns the playthrough URL namespace, such as `/play/:playthroughId/*`, and resolves guest ownership and case/version before mounting. The case owns the suffix and chooses its routing model. M0 does not require every internal view to be bookmarkable or a generic locked-route model. Navigation alone never authorizes protected data.

M0 action handlers synchronously inspect supplied case state and server-only configuration, validate an action, compute proposed state, and return outcomes/events for atomic platform persistence. They have no raw database access, arbitrary SQL, external HTTP calls, filesystem writes, background jobs, queues, or asynchronous side effects. These restrictions narrow M0 execution, not future gameplay possibilities; introduce external capabilities only when a concrete case requires them.

Iframe/document isolation, separate origins for case frontends, separately deployed applications, process isolation, additional backend languages, WASM, and runtime-loaded modules are deferred. A concrete requirement for document isolation reopens the frontend decision. Dependency boundaries are specified in ADR-0001; exact callback signatures remain an implementation detail to resolve against the two demos.
